2. What Terraform Is (Interview Definition)

Terraform = Infrastructure as Code tool built by HashiCorp, used to provision, modify, destroy, and automate infrastructure on:

AWS

Azure

GCP

VMware

On-prem
…using declarative configuration files.

Simple answer for interview:
Terraform lets you create cloud resources by writing code instead of clicking in the console.

3. Terraform Required Files
main.tf

Contains the actual resource definitions (EC2, VPC, S3, SG, etc.)

provider.tf

Specifies which cloud (AWS, GCP, Azure) we are using and which region/profile.

variables.tf

Reusable variables (AMI IDs, instance types, region, profile, etc.)

outputs.tf

Prints important resource info (public IP, instance ID, etc.).

terraform.tfstate

Stores the current state of cloud infrastructure.
Never push it to GitHub.

.gitignore

Must exclude:

terraform.tfstate
terraform.tfstate.backup
.terraform/
*.hcl
*.tfvars

4. Terraform Basic Commands (with meaning)

terraform init → downloads provider plugins

terraform plan → shows what will change

terraform apply → creates/modifies infrastructure

terraform destroy → deletes only Terraform-managed resources

7. Terraform State File (Critical Concept)

tfstate = brain of Terraform

If deleted → Terraform forgets all resources

Terraform may try to recreate everything

Never push state to GitHub

Always store state on remote backend (S3 + DynamoDB)

8. Pushing Terraform Code to GitHub

Workflow you practiced:

Create GitHub repo

Clone it

Create feature branch:

git checkout -b feature-01


Add/commit code:

git add .
git commit -m "Added Terraform EC2 code"


Push to branch:

git push origin feature-01


Open Pull Request

Review → Approve → Merge

Main branch stays protected

This is exactly how real companies work.
